# ADR-001 - Decisión Arquitectónica: Monolito Modular Flask

**Estado:** ACEPTADO EN LÍNEA BASE v1.0.0  
**Fecha:** 2026-11-07  
**Autor:** Arquitectura / Backend

## Contexto

Sistema de gestión agrícola para café y plátano. La primera línea base contemplaba los dominios `usuarios` y `lotes`; el estado actual también incluye `fincas`, `cultivos`, `labores`, `cosechas`, `insumos` y `eventos`.

Se requiere una arquitectura mantenible por un equipo pequeño, con separación clara de responsabilidades y sin sobreingeniería.

## Decisión

**Backend Python Flask** con **Application Factory**, **Flask Blueprints** y **Flask-SQLAlchemy/MySQL**. Los cambios de esquema se mantienen como SQL revisado; Flask-Migrate está en las dependencias, pero aún no se inicializa en la fábrica.

Dominios (`backend/app/modules/`) con capas sencillas:
1. **entities/** — Modelos SQLAlchemy (sin lógica de negocio)
2. **repositories/** — Consultas SQLAlchemy/ORM (solo acceso a BD)
3. **dtos/** — Esquemas Marshmallow (validación y serialización)
4. **services/** — Lógica de negocio, reglas, permisos, transacciones
5. **controllers/** — Blueprints Flask, rutas HTTP y respuestas JSON

Capa compartida (`backend/app/shared/`):
- `utils/app_exception.py` — `AppException` para errores HTTP JSON
- `utils/qr_generator.py` — `generate_qr_base64()`
- `constants.py` — constantes compartidas del dominio

## Alternativas descartadas

| Alternativa | Motivo de descarte |
|-------------|-------------------|
| Monolito tradicional | Mayor acoplamiento al mezclar HTTP, reglas y persistencia en un mismo lugar |
| Microservicios | Complejidad de red, seguridad, consistencia distribuida y observabilidad desproporcionada para dos dominios CRUD |
| SOA / eventos / mensajería | Solo si se identifican integraciones externas o trabajos prolongados; no añadir bus artificialmente |

## Consecuencias

- Menores dependencias, un solo despliegue conjunto
- Posible escalamiento vertical medido
- Trazabilidad clara entre capas y dominios
- No se implementa Flask-Migrate/Alembic automáticamente en v1.0 (migraciones manuales revisadas)

## Reglas de oro (aplicadas)

1. No lógica de negocio en controladores
2. No consultas SQL/SQLAlchemy en servicios (delegar al repositorio)
3. No acceso directo a BD desde controladores
4. Type hinting y docstrings en todo el código
5. `.env` no versionado (en `.gitignore`)
